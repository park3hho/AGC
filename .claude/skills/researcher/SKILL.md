# 리서처 AGC

> 사람용 요약이 AGC 화면에도 있다 — 제품조사·가격조사 제목 옆 ⓘ (FE `src/constants/researchRules.js`). **이 파일의 규칙을 바꾸면 그 파일도 같이 고친다.**

사람이 앱(FE)에서 하는 일과 똑같이 한다: **제품을 찾아 제품을 추가하고**, 그 제품을 골라 **가격 조사를 입력**한다.
입력은 모두 AGC API 로 한다. API 스펙 원문은 `docs/api-contract.md` — 이 문서와 다르면 그쪽이 맞다.

## 0. 먼저: 무엇을 채워야 하나 (API 가 받는 모양)

검색하기 전에 아래 두 모양을 머리에 넣고, **이 칸들을 채우는 정보만** 모은다. 필수(✅) 칸을 못 채우면 그 상품은 버리고 다음 후보로 간다.

**제품 — `POST /products`**
```json
{
  "title_cn": "✅ 타오바오 상품의 중국어 제품명 (브랜드 + 제품명 + 맛/용량은 빼고 핵심만)",
  "title_ko": "한국어 판매용 이름 (예: 동방수엽 무가당 차)",
  "photo_url": "대표 사진 — §2 에서 from-url 로 저장한 /files/... 주소",
  "category": "✅ beverage(병·캔·팩 음료) 또는 tea(우려 마시는 찻잎·티백)",
  "subcategory": "✅ §3-2 표에서 하나",
  "tea_form": "차(tea)만 — leaf 찻잎 · bag 티백 · coldbrew 냉침 티백 · powder 가루"
}
```
`code`(PR-YYMMDD-XXXX)·추가일은 BE 가 붙인다.

**가격 조사 — `POST /price-surveys`**
```json
{
  "product_code": "✅ 위에서 받은 PR-... 코드",
  "survey_date": "✅ 오늘 (KST, YYYY-MM-DD)",
  "taobao_url": "✅ 구매할 타오바오 상품 링크 (공식 판매몰 우선)",
  "photo_url": "제품 대표 사진 (보통 제품의 photo_url 그대로)",
  "options": [
    {"option1": "✅ 맛 이름 (한국어, 예: 재스민차)", "option2": "용량·입수 (예: 500ml×15병)", "price_cny": "✅ 39.90", "photo_url": "그 맛 사진 /files/..."}
  ],
  "coupang_min_price": 19900, "coupang_url": "https://...",
  "naver_min_price": null, "naver_url": null
}
```
- `options` 는 맛(option1) × 용량·입수(option2) 조합마다 한 줄. 같은 조합 두 번 금지.
- **option2 에는 반드시 총 용량 또는 무게 숫자(ml·L·g·kg)를 넣는다** (2026-10-30 사용자). AGC 는 이 숫자로 무게를 잡아 집운 배송비를 계산한다. 배송비는 **무게와 박스 크기**로 정해진다.
  - 개수만 있는 상품(드립백·스틱·티백·봉지·캔 개수 등)은 뒤에 무게를 붙인다: `20개입 (약 400g)`, `드립백10+동결건좐20 (약 600g)`, `1박스 10스틱 (약 500g)`.
  - 무게는 파라미터 `净含量`·`毛重`(총중량)·상세 이미지 → 같은 브랜드 비슷한 상품 순서로 찾는다. **못 찾으면 넛넉하게(크게) 잡는다** — 적게 적으면 배송비가 모자라 손해다. 추정치는 `약` 을 붙이고, 포장 무게까지 생각해 내용물보다 20~30% 더 적는다.
  - 부피가 큰 가벼운 상품(과자 봉지·선물 상자·여러 맛 세트)은 박스 크기가 배송비를 정한다(부피 무게 = 가로×세로×높이cm ÷ 6000). 상자 크기를 알면 option2 나 메모에 `상자 약 30×20×15cm` 처럼 적고, 모르면 **세 변 합 최소 50cm** 로 보고 그보다 크면 크게 적는다.
  - 숫자가 없으면 AGC 는 최소 상자(세 변 합 50cm, 약 0.77kg)로만 계산한다. 실제로 무겁거나 큰 상품은 배송비가 적게 잡혀 손해가 나니, 등록 뒤 가격 책정 화면에 주황 "최소 상자로 계산" 이 떠 있으면 option2 에 무게를 넣어 고친다.
- `price_cny` 는 그 옵션의 **타오바오 판매가(위안)**. 할인 쿠폰가가 아니라 페이지에 보이는 현재가.
- 쿠팡·네이버 칸은 없으면 비운다 (null).

## 1. 제품 검색

규칙:
- **검색·조사는 타오바오에서만** 한다 (s.taobao.com). 국내 비교만 예외 — 쿠팡·네이버쇼핑에서만, 없어도 됨.
- 구매 링크는 **공식 판매몰(旗舰店·官方旗舰店) 위주**. 공식몰이 없을 때만 판매량 많은 일반 판매자.
- **제조사를 확인**한다 (상품 상세의 品牌 / 生产商). 제조사를 모르면 `title_cn` 에 브랜드를 넣을 수 없으니 버린다.
- **음료 위주.**
- **신선식품 불가**: 과일, 냉장 제품 (집운 해운은 냉장이 아니고 약 15일 걸린다).
- **유제품·우유가 든 음료는 §1-2 집운 허용 확인을 통과한 것만** (2026-10-29 사용자 지시). 상온 멸균이어도 되는 것·안 되는 것·법적으로 막히는 것이 섞여 있다. 10-29 점검 54개 결과: **순수 우유·요구르트는 하나도 통과 못 함** → 후보에서 바로 뺀다. 밀크티·커피·일부 유산균 음료는 통과한 것이 있으니 하나씩 확인한다.
- 주류 불가. 건강기능식품·약재 성분 음료(凉茶 등 약초 들어간 것)는 피한다 — 국내에서 의약품 성분으로 막힐 수 있다.
- 이미 앱에 있는 제품인지 먼저 본다: `GET /products?q=<브랜드나 제품명>`. 있으면 새로 만들지 말고 그 코드로 가격 조사만 추가한다.

타오바오 화면은 로그인이 필요하다. **브라우저 창(built-in browser)에서 사용자가 로그인해 둔 상태로만** 본다. 로그인 화면이 나오면 멈추고 사용자에게 로그인해 달라고 한다 — 비밀번호를 대신 넣지 않는다.

타오바오 계정은 **리서치 전용 tb503763738723** (집운 ID YIEVGIN3) 으로만 본다. 이 계정으로 새 결제는 하지 않는다 (결제는 tb374865614765 전용, 2026-10-29 사용자).

### 1-2. 집운 허용 확인 (2026-10-29 사용자 지시 — 등록 전 필수)

제품을 AGC 에 넣기 **전에**, 그 판매처 상품이 한국으로 **집운(官方集运) 해운**으로 살 수 있는지 타오바오 주문 확인 화면으로 확인한다. **결제는 하지 않는다.** 유제품·우유 든 음료는 반드시, 그 밖의 음료도 가능하면 확인한다.

1. 상품 상세에서 조사할 옵션을 고르고 `立即购买` 을 누른다 (`humanClick`).
2. 열린 확인 화면(buy_now / confirm_order) 본문으로 판정한다:
   | 보이는 문구 | 판정 | 처리 |
   |---|---|---|
   | `集运-海运` + `首重` | 집운 가능 | 등록 진행 |
   | `不支持集运-海运` | 집운 미지원 | 그 판매처는 버린다 → 다른 판매처 확인 |
   | `无法购买或运送` (법규나 타오바오 정책으로 구매·운송 불가), 결제 금액 ¥0 | **판매 불가 (법적 제한)** | 제품을 버린다 |
   | 해외로 주문하는 버튼이 없음 (天猫超市 등) | 그 판매처 불가 | 다른 판매처 확인 |
3. 판정만 하고 확인 화면을 닫는다 (주문 제출·결제 버튼은 누르지 않는다).

- **판매처마다 결과가 다르다.** 같은 상품도 공식몰은 막히고 일반 가게는 열릴 수 있다. 한 판매처가 집운 미지원이면 다른 판매처를 확인하고, 통과한 판매처 링크를 `taobao_url` 로 쓴다.
- `无法购买或运送` 가 나온 제품은 다른 판매처에서 열려도 한국 통관(검역) 위험이 남으므로 등록하지 않는다.
- 확인 화면을 짧은 간격으로 많이 열면 타오바오 로그인이 풀린다 (10-27 관찰). 확인 화면 사이는 **30초 이상**, 10개마다 5분 쉰다.
- 결과(가능 / 미지원 / 판매 불가, 확인한 판매처)를 보고에 적는다. 보류 중인 등록 상품을 다시 확인할 때도 같은 방법을 쓴다.

### 1-1. 캡챠·접속 차단 대응 (계정 보호)

캡챠를 **무시하고 다른 페이지로 넘어가지 않는다.** 캡챠가 떠 있는데 계속 페이지를 열면 그게 가장 봇처럼 보이고 계정 제한으로 이어진다. 캡챠가 떠 있으면 상세 이미지·参数信息 도 가려져서 읽은 값도 틀린다.

**확인 시점**: 검색, 다음 페이지, 상품 클릭(새 탭 포함) 등 페이지가 바뀔 때마다, 값을 읽기 **전에** 아래 `taobaoBlock(page)` 로 확인한다.

```js
async function taobaoBlock(page) {
  if (/login\.(taobao|tmall)\.com/.test(page.url())) return { type: 'login' };
  for (const f of page.frames()) {
    const h = await f.locator('[id^="nc_"][id$="_n1z"], .btn_slide').first().boundingBox().catch(() => null);
    if (h) return { type: 'slider', frame: f, handle: h };
    if (/_____tmd_____|punish/.test(f.url())) return { type: 'challenge', frame: f };
  }
  const t = await page.evaluate(() => (document.body?.innerText || '').slice(0, 4000));
  const m = t.match(/访问异常[^\n]*|请按住滑块[^\n]*|拖动到最右边[^\n]*|验证码[^\n]*|请依次点击[^\n]*|请点击[^\n]*|请选择[^\n]*图[^\n]*/);
  return m ? { type: 'text', hint: m[0] } : null;
}
```

**걸리면** (`null` 이 아니면):
1. 그 자리에서 멈춘다. 탭을 닫거나, 다른 주소로 이동하거나, 새 탭을 열지 않는다.
2. **슬라이더**(请按住滑块，拖动到最右边 / 밀어서 확인하기): **2026-10-25부터 사용자가 직접 민다.** 자동 드래그는 4번 시도해 모두 서버 판정(error 코드)으로 실패했다.
   - 상품 상세에서 뜨면: 결과 클릭으로 열린 상세 탭은 사용자 화면에 안 보이므로, 그 탭의 주소를 `openTab(url)` 로 새 탭에 다시 띄운다 (대부분 이때 인증 없이 바로 열린다 — 그러면 그 탭으로 이어서 읽고 막힌 탭은 닫는다).
   - 새 탭에서도 슬라이더가 보이면: 오류 화면(새로 고치세요)이면 '새로 고치고'를 눌러 슬라이더를 다시 띄운 뒤, `notification` (requireInteraction) 으로 사용자에게 알리고 10초 간격으로 풀렸는지 확인한다. 15분 안에 안 풀리면 중단하고 보고한다.
   - (참고, 예전 방식) `captcha-solver` 스킬의 `captcha.drag` 로 한 번 푼다. 손잡이 가운데 → 트랙 오른쪽 끝 너머로, 단계는 30~50 사이 무작위, y 는 ±2px 흔든다.
   ```js
   const b = await taobaoBlock(page);
   const track = await b.frame.locator('[id^="nc_"][id$="__scale_text"], .nc_scale').first().boundingBox();
   const y = b.handle.y + b.handle.height / 2;
   await captcha.drag(page, { x: b.handle.x + b.handle.width / 2, y },
     { x: track.x + track.width + 8, y: y + (Math.random() * 4 - 2) }, { steps: 30 + Math.floor(Math.random() * 20) });
   ```
   3~5초 뒤 `taobaoBlock` 으로 다시 확인. "出错了 / 点击刷新" 이 나오면 그 글자를 눌러 새로 고친 뒤 **한 번만** 더 시도한다 (최대 2번).
3. **그림 고르기**(请依次点击… / 请选择所有包含…的图片 처럼 그림·글자를 눌러 고르는 것): 캡챠 영역만 잘라 본다 — `const box = await b.frame.frameElement().then(e => e.boundingBox())` (iframe 이 아니면 캡챠 상자 요소의 `boundingBox()`), `display(await page.screenshot({ clip: box }))`. 문제 문구를 읽고 맞는 칸·글자를 고른 뒤, 순서가 있으면 그 순서대로 `page.mouse.click(x, y, { delay: 80~200ms 무작위 })` 로 누른다. 누르는 위치는 칸 가운데에서 ±4px 흔들고, 클릭 사이는 0.6~1.5초 무작위로 쉰다. 확인 버튼(确认/提交/验证)이 있으면 누른다. 고르기 전에 확신이 없으면(문구가 안 읽힘, 그림이 애매함) 새로 고침 아이콘을 눌러 다른 문제를 받는다. 3~5초 뒤 `taobaoBlock` 으로 다시 확인, 슬라이더와 같이 **최대 2번**.
4. 글자 입력 캡챠(验证码 입력칸)는 `captcha.readText(page, box)` 로 읽어 넣는다. 최대 2번.
5. **그림 고르기·글자 입력을 2번 실패하거나, 위에 없는 종류의 캡챠**면 더 시도하지 않고 그날 타오바오 조사를 **중단**한다. 사용자가 직접 푸는 것은 **슬라이더뿐**이다 (2026-10-29 확인) — 그 밖의 캡챠는 풀어 달라고 하거나 기다리지 않는다. 여기까지 입력한 결과와 막힌 화면(주소·캡챠 종류)을 보고하고 끝낸다. 로그인 화면은 위 규칙대로 사용자에게 로그인을 요청한다.
6. **통과한 뒤**: 1~2분 쉬고, 다음 10번의 동작은 간격을 두 배(10초 + 무작위)로 늘린다.
7. 한 번 작업에서 캡챠가 **3번** 나오면 그날 타오바오 조사는 중단하고 보고한다.

**예방**:
- 상품 상세는 주소로 바로 열지 않는다(访问异常 이 잘 뜬다). 검색창에 입력 → 결과 클릭으로 연다.
- 동작 사이 간격은 5초 + 무작위, 클릭 위치·누르는 시간도 무작위. (2026-10-25 사용자: 이 기준과 아래 마우스·스크롤 시간 전부 ×1.15 로 진행)
- 天猫超市(티몰 직영몰) 상품은 배송지가 한국이라 재고가 0으로 보이는 경우가 많다 — 브랜드 旗舰店 을 먼저 찾는다.
- 같은 상품이 포장 방식만 다른 옵션(폼박스/종이박스 등)이면 가장 싼 것, 값이 같으면 가장 안전한 포장(폼박스)으로 기록한다 (2026-10-25 사용자).
- 마우스·스크롤은 아래 헬퍼로만 움직인다 (2026-10-24 사용자 지정). `locator.click()` · `page.mouse.click()` · `mouse.wheel` 한 번에 크게 · `scrollIntoView` 를 타오바오에서 직접 쓰지 않는다.
  - **휘어진 경로**: 현재 위치 → 목표를 직선이 아닌 베지어 곡선으로 (조절점을 경로 옆으로 거리의 10~30% 무작위로 띄움).
  - **속도 변화**: 처음 빠르고 목표 근처에서 느려진다 (ease-out). 단계 수는 거리에 비례해 15~40.
  - **지나쳤다 돌아오기**: 25% 확률로 목표를 3~8px 지나쳤다가 되돌아온다.
  - **멈칫**: 누르기 직전 0.1~0.4초 머문다. 누르는 시간 40~160ms.
  - **스크롤**: 한 번에 내리지 않고 80~240px 휠을 여러 번, 사이 0.08~0.35초. 가끔(15%) 조금 되올린다.

```js
const rnd = (a, b) => a + Math.random() * (b - a)
let cur = { x: rnd(200, 600), y: rnd(150, 400) } // 마지막 마우스 위치

async function humanMove(page, x, y) {
  const path = async (tx, ty) => {
    const dx = tx - cur.x, dy = ty - cur.y, dist = Math.hypot(dx, dy) || 1
    const off = dist * rnd(0.1, 0.3) * (Math.random() < 0.5 ? -1 : 1)
    const cx = cur.x + dx * rnd(0.3, 0.7) - (dy / dist) * off   // 경로 옆으로 띄운 조절점
    const cy = cur.y + dy * rnd(0.3, 0.7) + (dx / dist) * off
    const n = Math.round(Math.min(40, Math.max(15, dist / 15)))
    for (let i = 1; i <= n; i++) {
      const t = 1 - Math.pow(1 - i / n, 3)                           // ease-out
      const px = (1 - t) ** 2 * cur.x + 2 * (1 - t) * t * cx + t * t * tx
      const py = (1 - t) ** 2 * cur.y + 2 * (1 - t) * t * cy + t * t * ty
      await page.mouse.move(px, py)
      await sleep(rnd(6, 18))
    }
    cur = { x: tx, y: ty }
  }
  if (Math.random() < 0.25) {                                         // 지나쳤다 돌아오기
    const a = rnd(0, Math.PI * 2), d = rnd(3, 8)
    await path(x + Math.cos(a) * d, y + Math.sin(a) * d)
    await sleep(rnd(60, 180))
  }
  await path(x, y)
}

async function humanScroll(page, total) {                            // total: 내릴 px (음수면 올림)
  let done = 0
  while (Math.abs(done) < Math.abs(total)) {
    const step = Math.sign(total) * Math.min(Math.abs(total) - Math.abs(done), rnd(80, 240))
    await page.mouse.wheel(0, step); done += step
    await sleep(rnd(80, 350))
    if (Math.random() < 0.15) { await page.mouse.wheel(0, -step * rnd(0.2, 0.5)); await sleep(rnd(120, 300)) }
  }
}

async function humanClick(page, locator) {
  let box = await locator.boundingBox()
  const vh = page.viewportSize()?.height ?? 800
  if (box && (box.y < 60 || box.y + box.height > vh - 60)) {          // 화면 밖이면 나눠서 스크롤
    await humanScroll(page, box.y - vh * rnd(0.3, 0.5))
    box = await locator.boundingBox()
  }
  if (!box) throw new Error('클릭할 요소가 안 보임')
  const x = box.x + box.width * rnd(0.25, 0.75), y = box.y + box.height * rnd(0.3, 0.7)
  await humanMove(page, x, y)
  await sleep(rnd(100, 400))                                          // 멈칫
  await page.mouse.down(); await sleep(rnd(40, 160)); await page.mouse.up()
}
```
- 타오바오 탭은 한 번에 하나만. 서브 에이전트로 동시에 여러 타오바오 페이지를 열지 않는다 (같은 로그인 계정).
- 다 본 상품 탭은 닫고 다음으로 간다.

보고에 **캡챠 몇 번, 어떻게 넘겼는지**(종류 / 자동 통과 / 중단)를 적는다.

## 2. 사진 검색

규칙:
- **워터마크 없는 사진.** 판매자 로고·홍보 문구가 크게 박힌 사진은 쓰지 않는다.
- **수량이 정확해야 한다.** 옵션이 "15병"인데 사진에 1병만 있거나 24병이면 안 된다. **박스 사진은 상관없음** (박스가 그 수량 단위면 OK).
- **제품과 사진이 같은지 확인** — 패키지 디자인·용량 표기가 상품 페이지와 같아야 한다.
- **옵션(맛)별 사진을 최대한 모은다.** 못 찾은 맛은 `photo_url` 을 비운다 (억지로 다른 맛 사진을 넣지 않는다).
- **제품당 사진 5장 이상** (2026-10-25 사용자: 사진 5장이면 구매 전환율 +5%). 대표 사진 + 옵션 사진 + **추가 사진(갤러리 `photos`)** 을 합쳤을 때 서로 다른 사진이 5장이 되게 채운다. 갤러리는 타오바오 메인 이미지에서 고른다: 제품이 잘 보이는 사진(병·박스·연출 사진)은 되고, 성분표·수상 증명서·이벤트 안내서·판매자 로고·연예인 사진은 안 된다. 홍보 문구는 잘라낸 뒤 올린다 (`POST /uploads/photos`). 갤러리는 수량 규칙을 따르지 않아도 된다 (분위기·단품 사진 OK). 저장: `PATCH /products/{id}` `{"photos": ["/files/...", ...]}` (목록 전체 교체, 최대 10장, 대표 제외).

저장은 외부 주소를 그대로 쓰지 말고 **BE 에 저장**한다 (원본이 지워져도 남게):
```
POST /uploads/photos/from-url   {"url": "https://img.alicdn.com/...jpg"}
→ {"url": "/files/photos/2026/10/....jpg", ...}   ← 이 /files/... 를 photo_url 에 넣는다
```
타오바오 사진 주소가 `..._.webp` · `_400x400.jpg` 처럼 줄인 버전이면 접미사를 떼어 원본 주소로 저장한다.

## 3. 제품 입력

1. `GET /products?q=...` 로 중복 확인.
2. 없으면 `POST /products` → 응답의 `product.code` 를 기록.
3. 잘못 넣었으면 `PATCH /products/{id}` 로 고친다. 완전히 잘못된 제품이면 `DELETE /products/{id}` (소프트 삭제).

## 3-2. 분류 (2026-10-29 사용자 지시 — 등록 때 같이 넣는다)

자사몰 메뉴가 이 값으로 거른다. 이름으로 찾지 않는다. 값 목록 원본은 BE `utils/category.py` (`GET /products/categories`).

| 대분류 | 소분류 |
|-|-|
| `beverage` 음료 (따서 바로 마시는 완제품) | `soda` 탄산 · `juice` 주스 · `tea` 차음료 · `milktea` 밀크티 · `coffee` 커피 · `milk` 우유·두유 · `functional` 이온·기능성 · `traditional` 전통음료 |
| `tea` 차 (우려 마시는 찻잎·티백) | `green` 녹차 · `black` 홍차 · `oolong` 우롱·암차 · `white` 백차 · `puer` 보이·흑차 · `flower` 꽃차 · `blend` 블렌드·과일차. 형태 `tea_form` 도 넣는다 |

헷갈리는 경계:
- 탄산 차·요구르트맛 탄산 → `soda` (마셨을 때 탄산이 먼저). 과즙차(果汁茶) → `tea`.
- 코코넛워터 → `functional`, 코코넛밀크·유산균 음료·요구르트·견과·곡물 우유 → `milk`.
- 꿀레몬수·식초 음료·옥수수 주스 → `juice`. 쏸메이탕·녹두탕·크바스 → `traditional`.
- 무탄산 소다수(苏打水饮品, 약알칼리수) → `functional`. 브랜드 이름에 속지 않는다 (예: 可口可乐 淳茶舍 = 차).
- 병에 담긴 차 음료는 `beverage › tea`. `tea` 대분류는 찻잎·티백처럼 직접 우리는 것만.

보고에 제품마다 분류를 적는다 (예: `음료 › 차음료`).

## 3-1. 상세페이지·마켓용 정보도 같이 찾기 (2026-10-27 사용자 지시)

조사할 때 아래 정보를 한 번에 같이 찾는다. 나중에 상세페이지에 노란 `[[...]]` 빈칸으로 남거나 쿠팡에서 바코드 때문에 거절되는 일을 막기 위해서다.

| 항목 | 어디서 찾나 |
|---|---|
| 제조사 (공장 법인명) | 티몰 상세 파라미터 `厂名`·`厂址`, 없으면 포장 사진의 `生产商`·`委托方`·`被委托方` |
| 원재료 | 파라미터 `配料表`, 없거나 "详见包装"이면 포장 사진·상세 이미지의 `配料` 문구. **맛(옵션)마다 다르면 맛별로** |
| 알레르기 유발 성분 | 원재료에서 우유·대두·땅콩·밀·견과 등 확인, 포장의 `致敏物质` 문구 |
| 바코드 (GTIN, 보통 69로 시작하는 13자리) | 파라미터 `条形码`·`商品条码`, 포장 뒷면 사진. **맛·용량(옵션)마다 따로**. 못 찾으면 "못 찾음"으로 적고 임의 번호는 절대 넣지 않는다 |
| 소비기한·보관 방법 | 파라미터 `保质期`·`储藏方法` |

- **우선순위 (2026-10-29 사용자):** 이 정보는 "채우면 좋다" 수준이다. 티몰 상세 파라미터나 포장 사진에서 바로 보이는 것만 넣고, 안 보이면 비워 둔다. 원재료 라벨 이미지를 따로 찾아 읽거나 빈칸만 채우려고 추가 조사를 하지 않는다. 상세페이지의 노란 `[[...]]` 도 같은 기준 — 값이 있으면 채우고 없으면 그대로 둡니다.
- 확인 못 한 항목은 보고에 "못 찾음"으로 한 줄만 적는다.
- 저장 위치 (2026-10-27 추가):
  - 제품: `POST /products` 또는 `PATCH /products/{id}` 의 `manufacturer` · `ingredients` · `allergens` · `shelf_life` · `storage`
    (원재료가 맛마다 다르면 줄마다 `맛: 원재료`, 한국어로 옮긴다. 제조사는 중국어 법인명 그대로 적고 한국어 표기는 상세페이지에서)
  - 옵션: `POST /price-surveys` 의 `options[].barcode`, 나중에 찾으면 `PATCH /price-surveys/{id}/options/{option_id}` 의 `barcode`
  - 상세페이지 초안이 이 값으로 '제품 정보' 표를 채운다. 비워 두면 노란 `[[...]]` 로 남는다.

## 4. 가격 입력

1. 사람이 FE 에서 제품을 고르듯, §3 의 `product_code` 를 쓴다.
2. `POST /price-surveys` 로 조사 1건 + 옵션 전체를 한 번에 넣는다.
3. 고칠 게 있으면 `PATCH /price-surveys/{id}` (`options` 를 보내면 옵션 전체 교체). `survey_date`·제품은 못 바꾸므로 그럴 땐 `DELETE` 후 다시 등록.

## API 호출 방법

- 주소: `${AGC_API_URL:-http://127.0.0.1:8000}` (BE 가 이 PC 에서 돈다)
- 인증: 헤더 `X-API-Key`. 키는 환경변수 `AGC_API_KEY`, 없으면 파일 `~/.agc/api_key`.
  **키를 출력하거나 채팅·파일·커밋에 옮기지 않는다.** 명령 안에서 `$(cat ~/.agc/api_key)` 로만 읽는다.
- 키로는 제품·가격 조사·사진 API 만 된다. 다른 API 는 403 이 정상이다.
- **Windows Git Bash 에서 한글·중국어 JSON 을 `-d '...'` 로 보내면 깨진다** → JSON 을 UTF-8 파일로 쓰고 `--data-binary @파일` 로 보낸다 (파일은 scratchpad 에).

```bash
API="${AGC_API_URL:-http://127.0.0.1:8000}"
KEY="${AGC_API_KEY:-$(cat ~/.agc/api_key)}"
curl -s -H "X-API-Key: $KEY" "$API/products?q=东方树叶"
curl -s -H "X-API-Key: $KEY" -H "Content-Type: application/json; charset=utf-8" \
     --data-binary @product.json "$API/products"
```
